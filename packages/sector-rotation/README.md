# 台股概念股輪動圖（Sector Rotation Bubble Chart）

InvestAlpha 專案的一個功能頁面，把 nstock 概念股清單的成交金額資料，畫成一張
「資金強弱 × 動能加速度」的四象限泡泡圖，用來快速掃描目前市場資金在哪些概念股
族群之間輪動。

這個資料夾是**原始碼歸檔**，從主專案 `frontend/src/pages/SectorRotationPage.tsx`
與 `backend/routers/stocks.py` 複製整理出來，方便獨立閱讀、分享、或存查設計脈絡。
**不是**可直接執行的獨立專案——它假設跑在 investreport 既有的 FastAPI + React
架構裡，實際維護請回到主專案對應檔案。

```
packages/sector-rotation/
├── README.md                          本文件
├── backend/
│   └── sector_rotation.py             後端計算邏輯 + 3 個 API endpoint（節錄自 stocks.py）
└── frontend/
    ├── SectorRotationPage.tsx         前端頁面元件（原檔複製，未修改）
    └── api-client-snippet.ts          元件用到的 API client 型別定義（節錄）
```

## 功能總覽

| 檢視模式 | 說明 |
|---|---|
| 泡泡圖 | 主視圖，X/Y 軸決定位置，泡泡大小＝成交規模 |
| 方格熱圖 | 同一份資料改用方格排列，適合快速掃視全部族群 |
| 排行長條 | 依資金強弱由大到小排序的橫條圖 |
| 指標矩陣 | 表格形式，可依任意欄位排序 |

點擊任一族群泡泡可以「鑽入」（drill-down）看該族群內個股的分布；同一套 X/Y/
象限邏輯在概念層與個股層都適用（見下方「兩層計算」）。頁面右側另外有：

- **CP 值排行**：資金強於平均、但加速度偏低的族群（可能補漲）
- **抄底偵測**：資金弱於平均、但動能已經回升的族群（象限 2「觀望」）
- **AI 問答**：把當日全部族群資料整理成文字 context，串流呼叫 Gemini
  （`gemini-2.5-flash`）回答自然語言問題

## 資料流程

1. 前端 `sectorRotation()` 打 `GET /api/stocks/sector-rotation`
2. 後端有快取（4 小時 TTL）就直接回傳；沒有就用 `asyncio.create_task` 觸發背景
   計算 `_compute_sector_rotation()`，同時先回傳 `computing: true`，前端輪詢直到完成
3. 背景計算步驟：
   1. 打 nstock `strategy` API 拿全部概念股分類（groups → subGroups → conditions）
   2. 用 `_CUSTOM_SECTOR_ORDER`（本檔案裡的自訂 40 族群清單）比對、排序、過濾——
      只保留這份清單認得的族群，且排除成分股超過 30 檔的（通常是 ETF 型分類而非真正概念）
   3. 並發抓每個族群的成分股清單，再併發抓所有不重複個股的日K（`ns.get_daily`，
      8 併發上限），只留最近 22 根 K 棒
   4. 逐族群加總成分股的 20 日 / 5 日成交金額，算出 X（資金強弱）、Y（動能加速度）
4. 結果存進 in-memory cache（`_SECTOR_CHIP_CACHE`），供後續請求與 QA 問答共用

## 演算法設計：X 軸怎麼算

這是這個功能目前為止經過兩次修正才定案的部分，記錄下來避免以後重踩同樣的坑。

**Y 軸（動能加速度）** 一直很單純：`近5日均量 − 近20日均量`，正負皆有意義，沒有問題。

**X 軸（資金強弱）** 經歷了三個版本：

### v1：絕對成交金額（有 bug）
最早直接拿「20 日累積成交金額」當 X 值。這個數字**恆為正**（成交金額不可能是
負的），導致四象限裡「觀望」「退潮」兩個 x<0 的象限**永遠不會有泡泡**——甚至
連前端已經做好的「抄底偵測」功能都因此一直回傳空清單，卻沒人發現，因為畫面上
就是「剛好」沒有東西在那兩格，不會報錯。

### v2：相對平均值的絕對差（部分修正）
改成 `該族群金額 − 全部族群平均金額`，讓 X 有正有負，四象限開始都有資料。
但族群間的成交金額是**長尾分布**——龍頭族群（如「先進製程」，主要成分是台積電）
可能是冷門族群（如「醫材醫美」）的 1000～1600 倍。不管拿平均值還是中位數當
基準，這種尺度差距都會讓一兩個巨型族群主導整個座標軸範圍，其餘 20 幾個族群
全部被壓縮在畫面中央、彼此重疊看不清楚，軸刻度也會出現像「+32984%」這種
沒有意義的天文數字。

### v3：log2 比例偏離（目前版本）
改用比例而非絕對差：

```python
x = log2(該族群 20 日金額 / 全部族群平均金額)
```

- `x = 0` 代表剛好等於平均值
- `x = +1` 代表是平均值的 2 倍，`x = -1` 代表是平均值的一半，以此類推
- 用 log 把「倍數關係」壓縮成線性尺度，數量級差距不會直接炸開座標軸

同一套邏輯也用在「族群內個股」的 X 值計算（鑽入某族群後看到的泡泡），只是
基準換成該族群內成分股的平均值，而非全部族群的平均值。

**還有一個容易漏掉的細節**：log 比例的正負兩側幅度天生不對稱——分母（成交量
趨近 0）可以讓 `x` 趨近負無限大，但分子受市場總成交量限制，正的一側是有界的。
如果座標軸還是用單一個 `max(|x|)` 對稱展開（左右用同一個極值），那麼一旦某個
接近零成交量的冷門族群把負向極值拉得很大，正向的座標軸也會被錯誤地跟著拉伸，
出現「刻度數字跟畫面上泡泡對不上」的視覺 bug。修正方式是**左右兩側分開取各自
的極值**：

```ts
const maxPosX = Math.max(...allB.map(b => Math.max(b.x, 0)), 0.1);
const maxNegX = Math.max(...allB.map(b => Math.max(-b.x, 0)), 0.1);
const xMin = -maxNegX * 1.2, xMax = maxPosX * 1.2;
```

畫面上顯示的標籤把 `log2` 值換算回「比平均多／少幾 %」，比較直觀：

```ts
const pct = (Math.pow(2, x) - 1) * 100;   // x=+1 → +100%（是平均的 2 倍）
```

## 象限定義

| 象限 | 條件 | 名稱 | 意義 |
|---|---|---|---|
| 0 | x≥0, y≥0 | 主力 | 資金多於平均，且還在加速流入 |
| 1 | x≥0, y<0 | 輪動 | 資金多於平均，但動能開始轉弱 |
| 2 | x<0, y≥0 | 觀望 | 資金少於平均，但動能已經回升（可能是抄底機會） |
| 3 | x<0, y<0 | 退潮 | 資金少於平均，動能也在衰退 |

## 兩層計算（概念層 / 個股層）

同一個 `x`、`y`、`quadrant()` 邏輯同時用在兩個層級：

- **概念層**：每個泡泡是一個族群（如「AI 伺服器」），X 相對「全部 23 個族群的
  平均 20 日金額」
- **個股層**（鑽入後）：每個泡泡是一支個股，X 相對「該族群內成分股的平均 20 日金額」

兩層算出來的 `x` 單位一致（都是 log2 比例），所以前端可以共用同一套 `fmtAmt`、
`quadrant()`、軸刻度渲染邏輯，不需要為兩層分別寫格式化規則（這也是 v1/v2 版本
遺留的技術債之一——舊版用 `drillDown ? x : x*10` 這種特殊分支處理單位換算，
換成比例式之後就不再需要了）。

**後端**（`sector_rotation.py`，未內附，需從主專案取用）：
- `nstock.py` 的 `get_daily(stock_id)` — 個股日K資料

## 已知限制

- nstock 概念股分類清單會隨時間變動，`_CUSTOM_SECTOR_ORDER` 是手動維護的白名單，
  新族群要手動加進去才會顯示
- 個股資料抓取全部依賴 nstock API 可用性，該服務不穩定時整個族群計算會失敗
  （目前用 `try/except: pass` 靜默失敗，不會讓整個 API 掛掉，但也不會告訴使用者
  哪裡出錯）
- log2 比例在成交量極低（接近 0）的族群上會產生很大的負值，雖然已經用左右分開
  取極值解決了「拖累另一側刻度」的問題，但這類族群彼此之間的相對差異仍然不易
  在畫面上分辨（例如 -95% 和 -99% 視覺上很接近）
- 快取是 in-memory dict（`_SECTOR_CHIP_CACHE`），多台後端實例之間不會同步，重啟
  即遺失，需要重新觸發一次背景計算（約需數十秒到 1-2 分鐘，視 nstock API 回應速度）

## 修改紀錄摘要

| 版本 | 改動 | 原因 |
|---|---|---|
| v1 | X = 絕對 20 日成交金額 | 初版設計 |
| v2 | X = 金額 − 全族群平均 | 修正「觀望/退潮」象限永遠是空的 |
| v3 | X = log2(金額 / 全族群平均)，軸範圍左右分開取極值 | 修正 v2 座標軸被巨型族群主導、刻度數字失真的問題 |
